# IS-117 Student Review: Choosing an AI Career

*Perspective exercise, November 5, 2026.* This is a simulated walkthrough by a student taking IS-117 at NJIT, **not a report of an actual student usability test**.

## Task

> I am learning GitHub, Node.js, websites and web servers. I want to choose an emerging AI career that builds on web development and determine what I should learn next.

## My decision

**First choice: Junior Forward Deployed Engineer.** This role connects web development, APIs, databases, deployment and communication to AI projects. The [Wipro junior posting](/us-internships-entry-level) explicitly mentions 0–2 years, making it easier to understand as a possible first job. **Second choice: AI Product / Applied AI Engineer**, because I would like to build complete user-facing applications; however, I need more proof of junior-level opportunities before ranking it equally.

## Friction encountered and improvements

| Priority | Issue or challenge | Proposed improvement |
| --- | --- | --- |
| High | Role names overlap; an 'AI Engineer' title doesn't tell me whether I need ML research or web engineering | Add a consistent role-comparison matrix for coding, ML, customer interaction, and experience |
| High | It was initially hard to see **internships and junior roles before senior jobs** | Put internships and entry-level pages first in navigation and cross-link the next career stage |
| High | Remote listings can be state-restricted, hybrid, or truly US-wide | Label remote geography precisely, including citizenship and work authorization requirements |
| High | Posting links can expire; no evidence of when a role was checked | Add snapshot dates and direct employer URLs, and later implement link checking |
| Medium | A student may not know terms like RAG, MCP, observability or LLMOps | Add a beginner glossary and short examples |
| Medium | Requirements can be intimidating: Google's internship asks for production AI experience | Distinguish required from preferred skills and suggest smaller portfolio milestones |
| Medium | Salary figures without seniority and geography context mislead | Only show posting-specific figures with location and level caveats |
| Medium | No way to filter by role level, location or interest | Add a filterable jobs directory in a future iteration |
| Low | A static site cannot indicate whether a job is still open | Clearly label this as research rather than a live job board |

## A realistic learning plan

1. Build and deploy one full-stack app with a public GitHub repo.
2. Add an AI feature through an API and document data handling.
3. Build a small RAG or tool-calling feature and test it against known cases.
4. Add logging, basic security, error handling and evaluation.
5. Write a short case study: problem, architecture, failures, fixes and user value.
6. Compare the resulting portfolio against actual internship and junior requirements.

## Test verdict

The site is useful as a **research starting point** and helps me choose a first target role. It is not yet a complete decision tool: glossary, filters, source freshness, and a side-by-side skill comparison would improve it.
